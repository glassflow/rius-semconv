# Keys other producers write

Keys from other instrumentations that the Rius SDKs emit or the Rius
normalizers read. No upstream OpenTelemetry registry defines them, so this
registry describes them as their producers write them, with the decision the
normalizers take on each usage key. Their spellings under `gen_ai.*` are not
defined here, because only OpenTelemetry may define that namespace; the full
usage-key table, those included, is [out/docs/usage-keys.md](https://github.com/glassflow/rius-semconv/blob/main/out/docs/usage-keys.md).

Generated from [rius-semconv](https://github.com/glassflow/rius-semconv) 1.8.2, the Rius attribute registry, and updated on each of its releases. {/* x-release-please-version */}

## Notes

**[1] `llm.cost.total`:** Cost stays off the wire on purpose: the backend prices from the token
counts with its own table, so a producer's figure is never trusted.

**[2] `llm.invocation_parameters`:** The request-parameters bag OpenInference instrumentors emit.

**[3] `llm.token_count.completion_details.audio`:** A subset of the output count, never added to it.

**[4] `llm.token_count.prompt`:** Copied, never summed with the cache counts: every bundled instrumentor
already reports it inclusive of them.

**[5] `llm.token_count.prompt_details.audio`:** A subset of the input count, never added to it.

**[6] `llm.token_count.total`:** The conventions define no total: they record input and output and leave
the sum to the reader. The sink reads it for validation only.

**[7] `metadata.ai.response.avgOutputTokensPerSecond`:** @arizeai/openinference-vercel's metadata.\* mirror of
ai.response.avgOutputTokensPerSecond. No recording carries it: the
TypeScript SDK no longer runs that transform. An app can still run the
package's span processor itself on a provider the SDK bridges onto, and
its spans then carry the mirror, so the entry stays.

**[8] `llm.usage.reasoning_tokens`:** OpenLLMetry's reasoning count in older releases.

**[9] `llm.usage.total_tokens`:** OpenLLMetry's and Laminar's total, as gen_ai.usage.total_tokens.

**[10] `operation.cost`:** pydantic-ai's own price for the call. Cost stays off the wire on
purpose, as with llm.cost.total.

**[11] `pydantic_ai.cache.<key>`:** pydantic-ai's prompt-cache health diagnostics (the cached prefix a
conversation established, hit ratio, misses), not provider usage.

**[12] `ai.response.avgOutputTokensPerSecond`:** A throughput figure, not a count.

**[13] `ai.response.usage`:** @ai-sdk/otel's speech and transcription spans, with its usage option:
the provider's usage object whole, as a JSON string, in whatever units
the provider bills (tokens, seconds, characters). The integration also
writes its numeric leaves on the same span as gen_ai.usage.&lt;key&gt;, which
is what is read (input_tokens, output_tokens) or decided above, so
parsing this would count the same usage twice.

**[14] `ai.settings.maxOutputTokens`:** A request parameter, mapped to gen_ai.request.max_tokens (which the AI
SDK also writes itself on a model call).

**[15] `ai.usage.cachedInputTokens`:** v5's cache-read count, still written beside the detailed spelling by
v6. Without it cached input was priced as uncached.

**[16] `ai.usage.completionTokens`:** v5's output count on generateText and generateObject; as ai.usage.promptTokens.

**[17] `ai.usage.inputTokenDetails.noCacheTokens`:** The uncached remainder of ai.usage.inputTokens. The conventions record
the inclusive input count and the cached part; this is their difference.

**[18] `ai.usage.inputTokens`:** Inclusive of the cached tokens, as the canonical key is.

**[19] `ai.usage.outputTokenDetails.textTokens`:** The non-reasoning remainder of ai.usage.outputTokens; the conventions
record the inclusive output count and the reasoning part.

**[20] `ai.usage.promptTokens`:** v5's input count on generateText and generateObject, left unread on
purpose. On a model call the AI SDK writes the same value to
gen_ai.usage.input_tokens itself. On the generateText wrapper v5 takes
it from the LAST step's response, not the run's total (v5's streams and
v6 report the total under ai.usage.inputTokens), so mapping it to
rius.aggregated_usage.\* would put a short total under a key that
promises the whole run.

**[21] `ai.usage.reasoningTokens`:** v5's reasoning count, still written beside the detailed spelling by v6.

**[22] `ai.usage.tokens`:** An embedding call's input count (ai.embed, ai.embedMany and their doEmbed).

**[23] `ai.usage.totalTokens`:** A total; the conventions define none.
